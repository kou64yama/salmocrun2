# 設計判断

入力: [要件](../requirements-analysis/requirements.md)、[ストーリー](../user-stories/stories.md)、[開発方針](../practices-discovery/team-practices.md)、[構成要素](components.md)。

## ADR-001: 画面・認識・共有の分離

- **Context**: 一画面の体験に対し、認識と共有は異なる失敗条件を持つ。
- **Decision**: 画面が認識と共有を呼び出す三つの部品に分ける。
- **Consequences**: 責務を個別に検証できる一方、境界の取り決めが必要。画像をバックエンドへ送らない設計を維持する。
- **Alternatives Rejected**: 一つの部品にまとめる案は接続が少ないが、責務とテストが混在するため採用しない。

## ADR-002: 一時状態の単一所有

- **Context**: 選び直し時の非同期処理と画像・結果の対応が重要。
- **Decision**: 画面が一時状態を所有し、選択単位を識別して古い結果を破棄する。
- **Consequences**: 不一致の共有を防ぎ、閉じた後の履歴を持たない。画面側に状態管理が必要。
- **Alternatives Rejected**: 認識部品と画面がそれぞれ状態を所有する方式は、二重管理と不整合を招きやすい。

## ADR-003: 非同期の部品間操作

- **Context**: 認識・共有は完了まで待機や失敗が発生する。
- **Decision**: 画面から各部品を非同期に呼び出し、結果または失敗を受け取る。
- **Consequences**: 進行状態と失敗を表示できる一方、古い完了の抑止が必要。権限とユーザー操作に関するブラウザ制約を共有時に扱う。
- **Alternatives Rejected**: 同期呼び出しは長時間処理とブラウザ共有の性質に適合しない。

## ADR-004: コード領域の抽出

- **Context**: 対象画面にはコード以外の文字も含まれる。
- **Decision**: 対象スクリーンショットのコード表示領域を切り出し、その領域から候補を得る。提供画像の右下を初期候補とし、実装時に認識結果で検証する。具体的な座標と検証例は [構成要素](components.md) に記載する。
- **Consequences**: 周辺文字の混入を減らせる可能性があるが、画面の位置や画像サイズの違いに依存し、実画像での確認が必要。画像はブラウザ内で処理する。
- **Alternatives Rejected**: 画面全体の認識結果から直接候補を得る方法は、他の文字が混入しやすい。

## ADR-005: PWA 資源の所有

- **Context**: インストールと起動には画面以外の資源と設定が必要。
- **Decision**: PwaShell がエントリーポイント、マニフェスト、アイコンを所有し画面を起動する。
- **Consequences**: 導入に関する責務が明確になるが、画面との接続が必要。導入可否は優先対象の Chrome で確認する。
- **Alternatives Rejected**: 画面部品に資源と導入設定を混在させると、画面と配布資源の責務が曖昧になる。
